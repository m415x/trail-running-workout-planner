# KAN-849/T3 — Next.js 16.3.8 loopback 307: pnpm native patch contingency

**Date:** 2026-10-23. **Status:** focal technical GREEN accepted; candidate not integrated. **Jira:** KAN-849 comment 14039. **Parent:** KAN-625. This document is a **candidate-branch handoff**, not a statement about integrated `dev`.

## Cause, scope and exact artifact

Next.js 16.3.8 router `dist/server/lib/router-utils/resolve-routes.js` derives an internal `initURL` authority from the bound hostname. With `127.0.0.1`, next-intl `defaultLocale: es`, `localePrefix: as-needed`, and rewrite/canonicalization, an upstream loopback authority discrepancy caused an external HTTP 307 self-redirect. Tracked upstream discussion/fix: vercel/next.js#95917.

Candidate branch: `feat/KAN-849-pnpm-native-patch-candidate`; functional commit `a3ca597e51752093fc8c49e623be19201e549b8b`. Dependency `next@16.3.8`, `pnpm@12.4.1`. Native `pnpm patchedDependencies` stores `patches/next@16.3.8.patch`, metadata in `pnpm-workspace.yaml` and `pnpm-lock.yaml`, and `.gitattributes` LF rule. Exactly one compiled router `initUrl` expression is modified: loopback host values (`127.0.0.0/8` matching prescribed pattern, `localhost`, `::1`) are mapped to `localhost` for internal authority formation. Not a general Host or auth bypass. Application authorization code unchanged.

Patch SHA-256: `6405c9217c3f38afb8070d800f6c36459927ddc3ed7c8bfd62ba32d951af1912` (LF, no CRLF); pnpm lockfile Git blob after install: `1cfd78b83a0d1391a2f73f7f91b592cce9e9d0a9`. Historical first-PC patch-file hash `a8597d0c1614c565b01e75ee4ad46a3a13a45dc3043f1e1d7b6edb5cf1cb941c` identifies a *different patch representation*, not current artifact. Do not substitute hashes manually.
