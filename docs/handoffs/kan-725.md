# KAN-725 — Harness v2 workflow hardening

## Scope

KAN-725 hardens the repository workflow used by fresh chats and story closure. It is tooling/process infrastructure, not a product-domain feature.

## Delivered contract

- `pn test` is full-suite only and rejects positional test paths. Focused RED/GREEN evidence must use `pn tdd:red <test-file> [...]` and `pn tdd <test-file> [...]`.
- `pn tdd:red` / `pn tdd` already perform the repository sync; agents must not request a separate `git pull` before them.
- `pn tdd` includes the canonical typecheck; agents must not request a separate `pn tsc` afterward.
- Approved decomposition authorizes continuous RED → GREEN → recoverable checkpoint execution.
- Approval of the final closure task authorizes the routine sequence documentation → PR → review/checks → merge → post-merge reconciliation → Jira. Routine intermediate approvals are not required.
- A story is not fresh-chat-safe until integrated `dev`, Jira and durable documentation agree.
- Candidate/gate SHA, PR head, merge SHA and later documentation-only SHAs remain distinct evidence identities.
- `pn docs:handoff:check` validates that the current operational handoff, story handoff and documentation index are structurally published.
- Harness v2 is the current operational workflow; `harness-eval-v1` remains historical evaluation evidence.
