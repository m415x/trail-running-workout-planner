- Explicit fresh, reviewed legacy, versioned and rejected/unrecognized state handling.

## Operational contract

Do not delete `sqlite.db` or use `db:push` as the normal upgrade/recovery path. Preserve the database, use the canonical upgrade/verifier, and investigate unsupported states before mutation.

Schema bootstrap remains independent from fixture seeding so empty-state behavior can be exercised without fixture data.

## Deferred / separate scope

- Moving schema modules into a new `db/schemas/` hierarchy is a cross-cutting refactor and is outside KAN-407.
- Persistent migration of the legacy PAM/intensity contract remains outside KAN-407 and follows this stabilization work.
- `db/seed.ts` remains transitional for legacy planning/workout/session/log/shoe fixture ownership; KAN-407 does not claim complete elimination of that monolith.
