# KAN-724 — Effective Team audience routing and session navigation (pre-merge candidate)

## Authority and boundaries
- H2 verifies the Supabase session and resolves the internal EPT User. The validated active-Team context and current TeamMembership preset determine routing audience; the legacy `users.role` is never a routing authority.
- `lib/auth/audience-destination.ts` classifies a single current matching TeamMembership as Athlete or Coach shell (Assistant/Coach/Admin); missing, conflicting, inactive, expired or cross-Team evidence denies routing. When multiple memberships are active without a valid selected Team, `selection_required` remains distinct and never selects an arbitrary Team.
- Coach and Athlete layouts enforce audience-level redirects before rendering their shells; resource authorization still belongs to server-side H2/H3/H4/H5 boundaries. Route redirects and shell visibility never authorize data access.
- `resolveAudienceLoginDestination` accepts locale-safe `returnTo` only when compatible with the effective audience; incompatible or unsafe paths fall back to that audience's authorized landing. Existing linked sessions reaching Login are redirected through the same classification.
- The unresolved-audience surface remains fail-closed with accessible sign-out in ES/EN. No full Team selection UI was introduced in this story; if none is reusable, Team selection is an independent follow-up.
- After successful Supabase signOut and active-Team cookie clearance, the client navigates immediately to localized Login and refreshes routing. Failure leaves navigation unchanged and reports an error.
