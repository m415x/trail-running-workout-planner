# KAN-377 — Running reference handoff

Status: complete and integrated into `dev` via PR #10.

## Delivered behavior

KAN-377 resolves the running reference applicable to an athlete and explicit effective date from canonical `1000m_track` evidence established by KAN-376.

- Resolution returns an explicit discriminated result: `available | unknown`.
- Eligible evidence is active evidence for the owned athlete with `performedAt <= effectiveDate`.
- The applicable observation is the latest eligible one using deterministic ordering `performedAt → createdAt → id`.
- Future observations cannot alter a reference resolved for an earlier effective date.
- An available reference preserves source evaluation identity, protocol, performed date, observed distance/time and deterministic pace/speed derivatives.
- No reference snapshot/entity is persisted; the reference is resolved from canonical evidence on demand.
- Ownership is resolved before the evidence query. An unauthorized/cross-team athlete is returned as not found and the repository is not queried.
- Resolution is read-only and does not mutate field evidence, accepted planning, monitoring, Training Response or readiness.

## Persistence and security

The existing `field_performance_tests` persistence remains the sole authority. SQLite adds a date-bounded active-evidence query using athlete, lifecycle and effective-date predicates with canonical ordering.

No Supabase migration or parallel repository/entity was required. The existing PostgreSQL schema already indexes athlete/date and the KAN-376 RLS boundary remains applicable.

KAN-377 closure verification: `pn db:check:supabase` GREEN and `pn db:verify:supabase` GREEN. Full tests, lint and TypeScript were also GREEN before the final closure phase.

## Temporal semantics and limitation

KAN-377 answers: “given the canonical evidence known now, which active observation applies to effective date X?”

This is not a bitemporal model. A later correction/invalidation changes which currently canonical evidence is considered when resolving a historical effective date. The system does not reconstruct what was known at a prior system-time.

That limitation is explicit and accepted for this story; no persisted reference version or system-time history is introduced.

## Safety and deferred work

Missing evidence remains `unknown`; zero/default values are not synthesized. KAN-377 does not infer HRmax, HRrest, VO2max, PAM/MAS, thresholds or blood-pressure-derived physiology.

Z1–Z5 guidance, pace percentages, RPE/Talk Test, Tanaka/Karvonen, `HR_ZONES`, `ZONE_PAM_PERCENTAGES`, Athlete Stats presentation, evolution analytics, multi-test support, device ingestion and readiness remain outside this story.

KAN-378 must start from this boundary: canonical evidence → authorized temporal running reference → guidance. It must not read legacy physiology as a second authority or mutate accepted planning.
