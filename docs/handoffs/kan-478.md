## Delivered behavior

KAN-478 carries the H2 contract stabilized by KAN-474–KAN-477 into PostgreSQL/Supabase without redefining domain decisions. `db/supabase/schema.ts` exports the three H2 revision tables and migration `drizzle/supabase/0024_membership_billing_exceptions.sql` materializes them with SQLite-equivalent checks, foreign keys and partial unique indexes for the current revision.

The existing shared Drizzle billing adapter remains the persistence implementation for both environment schemas. H2 does not introduce a second PostgreSQL-specific repository or a second domain contract.

## Security boundary

All three H2 Supabase tables have RLS enabled and are included in the remote table/RLS verifier. KAN-478 deliberately creates no permissive RLS policies: identity/authentication/authorization remains a later phase. Reduction and extension facts are charge-scoped and do not duplicate athlete/team/payment identity; team/athlete isolation continues through the H1 charge relation plus application/persistence guards.

The Supabase verifier now checks the H2 table inventory, RLS, current-revision indexes, month/reduction checks and H2 foreign keys against the actually deployed database.
