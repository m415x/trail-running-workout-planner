## T1 implementation contract

- `getGroupTrainingPlans()` keeps its legacy array return type and its existing position, preserving older consumers and KAN-605 static section tests.
- `getCoachPlanningListResult()` is the only new public Server Action entry point. It obtains H2 authenticated EPT identity through existing Supabase verified-session flow, H3 active Team through the Next cookie-backed context, H4A `planning.manage` decision, and H4B per-Plan authorization with persisted group ownership.
- `lib/planning/coach-planning-list-operation.ts` is the shared server-owned operation. The Server Action delegates to this operation. Its dependencies are server-provided; there is no client-controlled identity or new endpoint.
- `lib/planning/coach-planning-list-reader.ts` preserves `denied`, `selection_required`, `invalid_context`, `empty`, `ready`, `error`. An authorized no-Plans result is EMPTY; unauthenticated/disallowed membership is DENY; H3 selection/invalid are not flattened into DENY; persistence exceptions yield ERROR.
- Authorization is performed before plan queries; authorized group IDs derive from persisted groups of the active Team. Plans are H4B-authorized individually and results exclude other Teams.
- The product's `planning.manage` is a non-delegable capability granted to Coach base preset; its default coverage is TEAM. Do not invent a delegated SPORTING_GROUP-only Coach role. H4B still checks Plan's Sporting Group ownership.
- T1 does not implement the landing, its ES/EN states, or permissions for the new-strategy CTA; these are T2.
