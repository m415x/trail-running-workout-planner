## Delivered contract

KAN-603 composes H1 identity/membership authority with H2 authenticated identity into a reusable H3 authorization model.

- TeamMembership is the sole organizational preset authority.
- Presets ATHLETE / ASSISTANT / COACH / ADMIN are explicit and non-hierarchical.
- `users.role` is legacy only and never an authorization fallback.
- AthleteProfile is an independent sporting subject; SELF requires a same-Team profile linked to the authenticated User.
- Executable scopes are SELF, SPORTING_GROUP and TEAM.
- ASSIGNED_ATHLETES is reserved and always fail-closed in H3.
- Capabilities are non-delegable by default. Structural authority is never delegable.
- ADMIN may grant only explicitly delegable non-structural authority inside the Team.
- COACH may grant only explicitly delegable sporting authority held as base authority; received grants cannot be redelegated.
- ASSISTANT and ATHLETE cannot grant delegation in this baseline.
- H3 introduces no generic DENY override system.

## Persistence

Authorization grants are durable, non-destructive historical records.

Canonical schema additions:

- SQLite `0019_known_mandroid.sql`
- PostgreSQL `0032_nice_fantastic_four.sql`

A grant records beneficiary, Team, concrete capability, executable scope/target, mandatory finite validity, grantor/reason and complete revocation metadata when revoked.

Physical invariants include:

- `effective_until` is NOT NULL;
- `effective_until > effective_from`;
- SPORTING_GROUP requires a target;
- SELF/TEAM forbid a target;
- revocation metadata is all-null or all-present;
- User/Team foreign keys use RESTRICT.

SQLite lifecycle verification is real local evidence. PostgreSQL evidence in KAN-603 is static migration/schema consistency only.

## Effective H2 → H3 boundary

The effective resolver applies this precedence:

1. authenticated H2 EPT User;
2. exactly one active TeamMembership for User + Team;
3. same-Team resource;
4. base capability from the membership preset;
5. SELF identity from same-Team AthleteProfile when relevant;
6. current, non-revoked matching grants;
7. executable scope coverage;
8. later domain rules;
9. allow.

Any absence, ambiguity, inconsistency or reserved scope produces deny.

The authenticated adapter accepts `RequireAuthenticatedActionResult`, denies every non-authenticated H2 state, removes actor identity from caller-facing input and injects only the H2-derived internal `userId`.
