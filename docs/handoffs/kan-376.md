# KAN-376 — 1000 m field-test evidence handoff

Status: completed. KAN-376 and implementation tasks KAN-381 through KAN-385 are Finalizada in Jira.

## Delivered behavior

KAN-376 establishes the canonical Epic 4 boundary for repeatable 1000 m track-test evidence.

- Protocol identity is `1000m_track`; distance is fixed at 1000 m.
- Canonical observation stores athlete, performed-at time, elapsed seconds, optional notes and explicit provenance.
- Average pace and speed are deterministic derivatives and are not parallel manually authoritative fields.
- Provenance is deliberately limited to `coach_manual` and `legacy_migration`.
- New evaluations append history instead of overwriting prior evidence.
- Correction validates a replacement and performs supersession plus replacement atomically. A failed replacement leaves the original active.
- Only explicit valid legacy `1000m_track` observations are eligible for promotion. Ambiguous legacy physiology is not reinterpreted.
- Missing heart-rate evidence remains unknown. KAN-376 does not infer HRmax, HRrest, VO2max, PAM/MAS, thresholds or blood-pressure-derived running physiology.

## Persistence and security baseline

SQLite and Supabase/PostgreSQL implement the field-performance evidence boundary. Supabase migration 0018 adds the required provenance column and constraint.

At KAN-376 closure, the real Supabase verification reported 37/37 application tables and RLS on 37/37. The provenance column was verified NOT NULL with the allowed `coach_manual | legacy_migration` constraint.

Application ownership resolution and persistence isolation preserve team/athlete boundaries; RLS remains the database-side protection for Supabase.

## Reusable implementation baseline

The next Epic 4 story may reuse:

- the field-performance-test domain observation and deterministic derivative functions;
- the SQLite repository and append-oriented history queries;
- atomic repository `replace` semantics for correction;
- the application boundary for coach registration/correction;
- explicit legacy promotion rules;
- matching SQLite/Supabase provenance constraints.

Do not introduce a parallel physiology authority or a generic multi-test/source framework unless a later story explicitly requires it.

## Limitations and deferred work

KAN-376 intentionally does not select a current running reference, calculate Z1-Z5 guidance, expose evolution UI, implement a protocol selector, support additional field tests, ingest devices, estimate VO2max, or automate the monthly test calendar.

Those downstream concerns remain assigned to later Epic 4 stories. The dependency direction remains evidence → reference → guidance → history/UI.
