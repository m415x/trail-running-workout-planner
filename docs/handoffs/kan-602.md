## Closure-time corrections discovered by the real walkthrough

### Child Server Component data reads

A protected parent layout did not prevent child Server Component reads from beginning before redirect resolution. KAN-642 therefore added explicit H2 guards before Athlete dashboard reads in `app/actions/dashboard-actions.ts`.

Covered reads:
- `getWeeklySchedule`
- `getCurrentAthletePlanningWeek`
- `getAthleteShoes`

This remains authentication-only and does not introduce KAN-603 capability/scope semantics.

### SQLite H1 false-head repair

The local SQLite verifier previously omitted the H1 tables `external_identity_links` and `team_memberships`, allowing metadata to appear current while the physical tables were absent.

KAN-642:
- added both H1 tables to the SQLite verifier;
- added bounded repair for falsely reconciled 0017/0018 metadata only when both physical H1 tables are absent;
- rejects partial/inconsistent H1 physical state;
- then lets the normal canonical Drizzle migration path recreate the tables.

The repaired local database subsequently completed `pn db:sqlite:upgrade` with schema verification PASS.

### Auth verifier environment provenance

The real Supabase Auth verifier now explicitly loads `.env.local`, so its credentials/configuration no longer depend on inherited shell variables. Secrets remain local and uncommitted.

### Coach logout Base UI contract

The visible Coach logout item was wired with Radix-style `onSelect`, while the project uses Base UI `Menu.Item`. KAN-642 changed the handler to `onClick`, after which the real browser walkthrough confirmed sign-out and protected post-logout redirect.

## Real Supabase/browser walkthrough evidence
